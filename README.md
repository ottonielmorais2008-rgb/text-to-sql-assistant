# Text-to-SQL Assistant

**Live demo: https://text-to-sql-assistant-tau.vercel.app**

[![CI](https://github.com/ottonielmorais2008-rgb/text-to-sql-assistant/actions/workflows/ci.yml/badge.svg)](https://github.com/ottonielmorais2008-rgb/text-to-sql-assistant/actions/workflows/ci.yml)

Ask a question about a small fictional online shop in plain English, for example *"What are the 3 best-selling products?"*.
Gemini reads the schema and writes a SQL query, the server validates it and runs it on a **read-only** SQLite database,
and the page shows a short answer, the result table and the exact SQL that was used.

## How it works

1. `POST /api/ask` receives the question (5–300 characters).
2. Gemini (`gemini-3.5-flash-lite`, via the Vercel AI SDK) gets the schema and returns a structured `{ sql }` object (max 400 output tokens).
3. `lib/validate.ts` checks the SQL (see below). Anything that fails is rejected before touching the database.
4. `lib/db.ts` runs it with Node's built-in `node:sqlite` on `data/shop.db`, opened with `readOnly: true`, wrapped in `LIMIT 201` and a 2 s time budget.
5. A second short call (max 200 tokens) turns the first rows into a one- or two-sentence answer.

The API key lives only in a server-side environment variable on Vercel; the browser never sees it.

### Data

`data/shop.db` (~540 rows of invented data) is generated by `npm run seed` from a fixed seed:
`customers` (60), `products` (20), `orders` (150, all in 2026) and `order_items` (306).

## Risks of letting an LLM write SQL (and what this project does about them)

| Risk | Mitigation here |
| --- | --- |
| **Destructive or write queries** (`DELETE`, `DROP`, `UPDATE`) generated by mistake or via prompt injection | The database connection is opened read-only, *and* the validator only accepts a single statement starting with `SELECT` or `WITH`, blocking write/DDL keywords. Two independent layers. |
| **Stacked statements** (`SELECT 1; DROP TABLE …`) | Any `;` outside string literals (other than a trailing one) is rejected. |
| **Engine features that escape the sandbox** (`ATTACH`, `PRAGMA`, `load_extension`, `sqlite_master`) | Blocked by keyword list. The DB file contains no sensitive data anyway. |
| **Hidden payloads in comments** | `--` and `/* */` are rejected. |
| **Resource exhaustion** (huge results, infinite `WITH RECURSIVE`) | `RECURSIVE` is blocked, results are capped at 200 rows and iteration aborts after 2 s. |
| **Prompt injection in the question** | The system prompt tells the model to ignore conflicting instructions; even if it obeys the attacker, the SQL still has to pass the validator and the read-only connection. |
| **Plausible but wrong answers** | The page always shows the generated SQL and the raw table so the user can verify the answer, and the eval set below measures accuracy. |
| **Cost / abuse** | Question length limit, small `maxOutputTokens`, free-tier model. |

A keyword denylist is not a full SQL parser. In a real system you would also use a dedicated low-privilege database role, views
that expose only allowed columns, statement timeouts on the server and per-user rate limiting.

## Evaluation

`evals/questions.json` holds 14 questions, each with a reference SQL query whose result is the expected answer.
`npm run eval` sends every question through the real pipeline and checks that the expected value appears in the first result row.

Results (5 Nov 2026, `gemini-3.5-flash-lite`, free tier), two runs:

| Run | Score | Failures |
| --- | --- | --- |
| 1 | 13/14 | 1 × free-tier rate limit (HTTP 429), not a wrong answer |
| 2 | 13/14 | 1 × "model experiencing high demand" API error, not a wrong answer |

Every question was answered correctly in at least one run; no generated query returned a wrong result.

## Tests and CI

- `npm test`: 24 offline tests for the SQL validator (accepted/rejected queries) and the database layer (row cap, read-only connection, input limits). No API key needed.
- GitHub Actions runs type-check, tests and a production build on Node 22 for every push and pull request, with no secrets.

## Tech stack

Next.js 16 (App Router), React 19, Tailwind CSS 4, Vercel AI SDK with the Google provider, Zod, `node:sqlite`, TypeScript, deployed on Vercel.

## Run locally

```bash
npm install
echo "GOOGLE_GENERATIVE_AI_API_KEY=your-key" > .env.local   # free key from Google AI Studio
npm run dev          # then open http://localhost:3000
npm test             # offline tests
npm run eval         # needs the key
```

Requires Node 22.13 or newer.
